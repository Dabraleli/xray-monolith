# 80. Настройки нового мира первым игроком — сборка 65

05.10.2026. Скриптовое обновление; движок остаётся от сборки 62.

## Использование

1. Для нового мира запустить `Start-Server.bat new`.
2. Запустить `Play-Coop.cmd`, открыть кооперативное меню и «Персонаж».
3. Выбрать сложности игры и экономики, состояние галки «Открытая зона», завершить создание и подключиться первым.

Сервер принимает эти параметры один раз и сразу применяет их, без ручного перезапуска. Последующие игроки получают серверные правила. Обычный `Start-Server.bat` продолжает последний сейв; настройки из меню не перезаписывают его. Сейв, созданный до сборки 65, также сохраняет свои правила.

Если персонаж создан старой версией меню, для настройки нового мира нужно снова открыть «Персонаж»: раньше выбранные сложности удалялись без сохранения. При отсутствии выбора первый игрок увидит подсказку. Право первоначального выбора закреплено за именем первого готового игрока, включая его переподключение.

## Реализация

`coop_menu` сохраняет три значения в профиле `[coop]` перед очисткой полей одиночного старта. `coop_world_settings` использует существующий Lua-канал; клиент может передать только два номера пресетов 1–3 и булево значение. Другой игрок, повторный или некорректный запрос не меняет правила.

В общем Lua-состоянии сохраняется маркер `coop_world_settings` с владельцем и признаком готовности. Новый мир ожидает выбора; загруженный старый мир без маркера считается уже настроенным. Сохранённый новый мир, ещё ожидающий выбора, продолжает ожидание после загрузки.

Применение выполняется в обновлении мирового актора, вне контекста отправителя. Используется собственный `on_game_load` модуля `game_difficulties`, найденный среди upvalue его `on_game_start`; остальные загрузочные callbacks не вызываются. Это обновляет реальные локальные таблицы, консольные параметры и функции сложности. Прежняя передача присваивала внешние поля `gameplay/economy`, которые модуль не читал.

Сервер пересчитывает коэффициенты из своего `plugins/difficulty.ltx`, обновляет таблицы лута и кандидатов для тайников, открывает маршруты и добавляет их метки при включённой открытой зоне. Клиенты получают фактические коэффициенты, включая индивидуальные изменения старого сейва, а не только номера пресетов. Штатные файлы модпака не заменяются.

Уже созданные при запуске мира предметы и снаряжение NPC не генерируются заново. Обновление меняет текущие правила и дальнейшие расчёты; полной повторной генерации мира под выбранный пресет здесь нет. Остальные режимы одиночного старта (сюжет, Warfare, Ironman и т. п.) в этот этап не входят.

## Проверки и доставка

`implementation/test_world_settings65.lua` загружает настоящие модули сложности и кооперативного меню с имитацией движковых служб. Проверяются сохранение выбора меню, первый/второй игрок, некорректные параметры, повторный запрос, закрытая зона, защита старых сейвов, сохранённое ожидание выбора и передача нестандартных коэффициентов.

`implementation/prepare_world_settings65.py` создаёт отдельный сервер и два клиента Anomaly. У первого выбор 3/2/открытая, у второго 1/1/закрытая. Проверяются единые правила, сохранение `rules65`, загрузка и автоматическое возвращение обоих клиентов. Окончательный прогон: `runtime/world-settings-65-final`; результаты: `evidence/builds/world-settings-65/checks.json` и логи рядом. Полная GAMMA и игра на разных ПК остаются для игрового тестирования.

`implementation/package_world_settings65.py` устанавливает четыре кооперативных скрипта: обычный запуск — локальный комплект; `--host` — `D:/Gamma-Coop-Host-42`; `--repo` — рабочий репозиторий. Перед заменой создаются резервные копии, проверяются хеши, конфиги и сейвы не заменяются. Патч: `delivery/Anomaly-Coop-Patch-64-to-65.zip`.
